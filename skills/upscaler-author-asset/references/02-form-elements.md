# 02 — HTML custom elements (`<form-*>` and `<format-*>`)

Assets embed two HTML custom element families in their Markdown bodies:

| Family | Purpose | Where valid | Whitelist |
| --- | --- | --- | --- |
| `<form-*>` | Field widgets | Registers, records, courses (**not** documents) | 17 elements |
| `<format-*>` | Image / file attachment blocks | **Any** asset category | `format-image`, `format-file` |

Both families share the attribute grammar below but deserialise to different Slate node shapes. **Never invent new tags**; unknown names are silently dropped.

## Shared attribute grammar

These rules apply to both families. Per-family exceptions are called out inline.

1. **Every attribute value is a quoted string.** `required="true"`, never `required=true` / bare `required` / `required="True"`.
2. **String attributes use double quotes**: `name="ff_..."`, `fileUid="..."`, `title="..."`.
3. **JSON attributes use single quotes** wrapping JSON with double quotes inside: `values='[{"text":"A","color":null}]'`, `fileList='[{"uid":"...","name":"..."}]'`.
4. **Opening and closing tags on every element**: `<form-text ...></form-text>`. Self-closing (`/>`) is **not** allowed for `<form-*>`; it **is** allowed for `<format-*>`.
5. Every element renders on its own line, separated from siblings by a blank line.

Form-element-only rules (do not apply to `<format-*>`):

6. **`name`** is an ID generated by `scripts/generate_field_id.py` (`ff_` + 28 base62 chars from `[A-Za-z0-9]` — no underscore, no hyphen). Never hand-craft; never reuse across the asset. An id with characters outside `[A-Za-z0-9_]` (e.g. a hyphen) is silently dropped by the platform's `select_values` projection, so the field stops resolving even though create succeeds.
7. **`title`** carries the human-readable label.
8. **`guidance`** is 2–4 sentences explaining what to enter and why. Never single words like "Enter the owner".
9. **`placeholder`** is an example prefixed with `E.g.`. Use `placeholder=""` for date / time / member fields when no example applies. `form-radio`, `form-checkbox`, and `form-recordlink` take **no** `placeholder` at all — omit the attribute on them entirely.
10. Sections begin with `## Heading`, blank line, `---`, blank line, first element. `---` appears **only** between heading and first field, never after fields.

## Tier 1 — freely generate

These 11 elements are safe to emit without external configuration.

### 1. `form-text` — single-line text

Required attrs: `name`, `title`, `required`, `placeholder`, `guidance`.

```html
<form-text name="ff_R7kXmPqW3vNcYdL5aQjB8tHu1wE2" title="Risk Owner"
  required="true" placeholder="E.g. IT Security Manager"
  guidance="Person accountable for managing this risk."></form-text>
```

Pitfall: using `form-text` for multi-paragraph input — use `form-text-area` instead.

### 2. `form-text-area` — multi-line text

Same required attrs as `form-text`; add optional `markdown="true"` to allow Markdown input.

```html
<form-text-area name="ff_BhJ2sT4wAaLe9FxG1nO5cPvR6uKy" title="Risk Description"
  required="true" placeholder="E.g. Unauthorised access to customer data."
  guidance="Describe the risk scenario and potential impact in detail."></form-text-area>
```

### 3. `form-number` — numeric input

```html
<form-number name="ff_ncxZeM0UGACqPJGxF1gnMzRUCpsj" title="Estimated Cost"
  required="false" placeholder="E.g. 50000"
  guidance="Enter the estimated financial impact in GBP."></form-number>
```

Optional attrs: `precision`, `step`, `min`, `max` (passed to the number input). To make a number auto-computed, set `calculated="true"` and `formula="..."`, where the formula references other fields as `{{ff_id}}`. Valid formula variables are `form-number` fields, `form-table` columns, and any select/radio with `supportCalculatedValue="true"`. Never pre-fill a calculated field — the platform recomputes and overwrites it on every form change.

### 4. `form-select` — dropdown (single or multi)

Required attrs: standard + `mode`, `values`. `mode=""` for single-select, `mode="multiple"` for multi-select. `values` is a JSON array of `{"text": "...", "color": null | "<colour>"}` objects (plain strings are also accepted); each object may additionally carry a numeric `"calculatedValue"`. For single-select only (`mode=""`), add `supportCalculatedValue="true"` to let `form-number` formulas reference this field (it has no effect with `mode="multiple"`). The stored value of a select is always the option **text**, never the `calculatedValue` number.

```html
<form-select name="ff_Wm3uKjNpQ7vHgXdYzLcEsB9tAu4o" title="Risk Category"
  required="true" placeholder="E.g. Operational"
  guidance="Select the category that best describes this risk." mode=""
  values='[{"text":"Strategic","color":null},{"text":"Operational","color":null},{"text":"Financial","color":null},{"text":"Compliance","color":null}]'></form-select>
```

Pitfall: wrapping the JSON in double quotes (`values="[...]"`) — the inner double quotes break. Always single quotes.

### 5. `form-radio` — single-choice button group

Required attrs: standard + `optionType="button"`, `values` (array of `{"text":..., "color":...}` objects; each may carry a numeric `"calculatedValue"`, enabled by `supportCalculatedValue="true"` — see `form-select`). Do **not** write a `buttonStyle` attribute — it is ignored; the platform renders outline buttons automatically when values carry colours and solid buttons when they do not.

```html
<form-radio name="ff_vZhrkEZ4Y6WjbHRSK222odyzXUln" title="Likelihood" required="true"
  guidance="Assess the probability of this risk occurring."
  optionType="button"
  values='[{"text":"1 - Rare","color":"green"},{"text":"2 - Unlikely","color":"cyan"},{"text":"3 - Possible","color":"gold"},{"text":"4 - Likely","color":"orange"},{"text":"5 - Certain","color":"volcano"}]'></form-radio>
```

Pitfall: forgetting `optionType="button"` — the field renders as raw radio circles without it.

### 6. `form-checkbox` — multi-choice checkbox group

Required attrs: standard + `direction="horizontal" | "vertical"`, `values`. **`values` is a JSON array of plain strings**, not objects.

```html
<form-checkbox name="ff_VsUILUDAbly0HhEl936jVB8kMZ9x" title="Data Categories"
  required="false" guidance="Select all categories of data involved."
  direction="horizontal"
  values='["Personal Data","Financial Data","Health Data","Proprietary Data"]'></form-checkbox>
```

Pitfall: using object values (`[{"text":"..."}]`) — the form renders blank. Checkbox `values` are strings.

### 7. `form-date-picker` — date selection

Required attrs: standard + `defaultToday="true" | "false"`. Optional `picker`: `date` (default) | `week` | `month` | `quarter` | `year`. Each picker stores a differently formatted string value (`YYYY-MM-DD`, `YYYY-ww[th]`, `YYYY-MM`, `YYYY-[Q]Q`, `YYYY` respectively).

```html
<form-date-picker name="ff_Qf7oEbHgK1pBaS4xJ6wYmCvDr2uK" title="Next Review Date"
  required="false" placeholder=""
  guidance="Select the date for the next scheduled review."
  defaultToday="false"></form-date-picker>
```

Pitfall: adding a non-empty `placeholder` — dates render a date picker icon, so use `placeholder=""`.

### 8. `form-time-picker` — time selection

Required attrs: standard + `use12Hours="true" | "false"`, `defaultNow="true" | "false"`.

```html
<form-time-picker name="ff_hJ6Uwp51qX8bYApd4UJRDPqXjB85" title="Detection Time"
  required="false" placeholder=""
  guidance="Record the time the incident was first detected."
  use12Hours="false" defaultNow="false"></form-time-picker>
```

### 9. `form-auto-increment` — sequential ID generator

Required attrs: standard + `nextNumber`, `addLeadingZeros`, `expectedMaxNumber`, `prefix` (3–4 uppercase letters + `-`).

```html
<form-auto-increment name="ff_PU3B0xszJ94JJZUQSQ6q5aOSdut8" title="Risk Number"
  required="true" placeholder="E.g. RSK-000001"
  guidance="Auto-assigned sequential ID for each new risk."
  nextNumber="1" addLeadingZeros="true" expectedMaxNumber="999999"
  prefix="RSK-"></form-auto-increment>
```

Common prefixes by context: `RSK-` (risk), `AUD-` (audit), `IMP-` (improvement), `INC-` (incident).

### 10. `form-member` — org member / group picker

Required attrs: standard + `multiple="true" | "false"`, `includeGroups="true" | "false"`.

Optional: `defaultCurrentUser="true" | "false"` (default false). When true, the field pre-fills with the current user (an array containing them when `multiple="true"`). Useful for "Reported by", "Completed by", or "Assigned Owner" fields in incident and audit records.

```html
<form-member name="ff_xRLZgwjU6tVIXbLWSDGvkHoF1ZOZ" title="Assigned Owner"
  required="true" placeholder=""
  guidance="Select the team member responsible for this item."
  multiple="false" includeGroups="false"></form-member>
```

### 11. `form-upload` — file upload

Required attrs: standard + `multiple`.

```html
<form-upload name="ff_c4OSSwt7krDem9z1mfaBvlfVKaGQ" title="Supporting Evidence"
  required="false" placeholder=""
  guidance="Upload supporting evidence such as screenshots, logs, or reports."
  multiple="true"></form-upload>
```

Upload limits are enforced **globally** by the platform, not per-field: max 50 MB per file, max 30 files, and a platform-wide extension allow-list (common document, spreadsheet, presentation, image, archive, and data formats). Do **not** author `maxCount`, `maxSize`, or `accept` — the deserialiser stores unknown attributes harmlessly, but the renderer and backend ignore them, so they only misdocument the field.

## Tier 2 — placeholder references only

These 4 elements reference IDs that exist in the user's tenant. Emit them with placeholder IDs and a TODO comment telling the user to replace them.

### 12. `form-table` — embedded table with typed columns

`columns` is complex JSON: array of `{"key", "title", "dataIndex", "type", "options"}`. Each column's `type` must be one of exactly **12 embeddable elements**: `form-text`, `form-text-area`, `form-date-picker`, `form-time-picker`, `form-number`, `form-select`, `form-checkbox`, `form-radio`, `form-member`, `form-lookup`, `form-upload`, `form-recordlink`. Never emit `form-table` (tables do not nest), `form-assessment`, `form-asset-picker`, `form-diagram`, `form-auto-increment`, or `form-framework-requirement-picker` as a column type — the platform stores such columns without complaint, but the web editor cannot handle them (the table designer hides the column and the editable table fails to render it).

Optional table-level attrs: `minRows` and `maxRows` (numeric, default 0 = no limit). `minRows` adds a row-count validator ("At least N row(s) required"); `maxRows` disables the Add-row button once the table reaches N rows. Emit them only when the asset needs them (e.g. `minRows="1"` on a findings table that must not ship empty).

```html
<form-table name="ff_O1ccCRpMTquXfIaPKTcXK1VGVkiH" title="Findings Table"
  required="false" placeholder=""
  guidance="Document each audit finding as a row."
  columns='[{"key":"col-id","title":"Finding ID","dataIndex":"col-id","type":"form-text","options":{"title":"Finding ID","placeholder":"E.g. F-001","guidance":"","required":false}},{"key":"col-severity","title":"Severity","dataIndex":"col-severity","type":"form-radio","options":{"title":"Severity","guidance":"","required":false,"optionType":"button","values":[{"text":"Minor","color":"gold"},{"text":"Major","color":"volcano"},{"text":"Critical","color":"magenta"}]}}]'></form-table>
```

Column `key` / `dataIndex` must be identical, unique within the table, and must never contain a dot (the platform flattens table schema keys as `<table ff_ id>.<column key>`, and the CLI splits `Table.Column` paths on dots). Dot-free hand-written slugs are accepted; the editor UI mints `ff_*` ids for columns it creates, so `ff_*`-style keys match platform convention if you prefer it. Column `options` do **not** need a `name` (validation waives it for columns and nothing reads it). The base62 `ff_` rule applies to field-level `name` attributes only — column keys never pass through the `select_values` projection.

### 13. `form-lookup` — reference another register

`filterParentId` holds the target register definition ID.

```html
<!-- TODO: replace REGISTER_ID_HERE with the actual register definition id -->
<form-lookup name="ff_GjtyQCwg3lqphgNAL6F1TOtIUPwN" title="Related Risks"
  required="false" placeholder=""
  guidance="Select related risks from the risk register."
  multiple="true" filterParentId='["REGISTER_ID_HERE"]'></form-lookup>
```

### 14. `form-recordlink` — link to record definitions

```html
<!-- TODO: replace RECORD_DEF_ID with an actual record definition id -->
<form-recordlink name="ff_eI40UhxtCdNMsyENRbFRMUBivFQj" title="Related Audits"
  required="false" guidance="Link to related audit records if applicable."
  recordDefinitions='[{"label":"Internal Audit Record","key":"RECORD_DEF_ID","value":"RECORD_DEF_ID"}]'></form-recordlink>
```

`recordDefinitions` entries **must** be objects with a string `value` (the published `rd_*` id), plus `key` (same id) and `label` (the definition title) — an array of plain id strings fails the platform validator. No `placeholder` on this element.

### 15. `form-asset-picker` — platform asset picker

```html
<form-asset-picker name="ff_Faj55w5O66IyCZvQMfgk2Ic1EtB2" title="Related Assets"
  required="false" placeholder=""
  guidance="Select any related assets from the system."
  multiple="true" sources='["document_definition","register_definition","record_definition"]'></form-asset-picker>
```

The only legal `sources` values are `record_definition`, `register_definition`, and `document_definition` (the designer offers exactly these three). An **empty** `sources` renders a "Please select a source" alert; a non-empty list containing unrecognised values (e.g. `"asset"`, `"item"`) is accepted silently at author time and renders a picker with zero options ("No items") because the backend ignores unknown source keys — a silently broken field, not an alert.

## Tier 3 — skip entirely (asset-type-specific)

| Element | Where NOT to use |
| --- | --- |
| `form-assessment` | **Only** in courses (one per lesson). Do not emit in registers or records. |
| `form-diagram` | Skip in all generated assets — requires interactive canvas. |
| `form-framework-requirement-picker` | Read-only: appears in exported definitions, but the markdown deserialiser drops it on import. Never author. |

### 16. `form-assessment` — course quiz (**courses only, one per lesson, ≥3 questions**)

Uses **single-quoted attributes** wrapping a JSON `questions` array. Each question has `id`, `label`, and `answers` (3 per question with one `isCorrect: true`, per the platform's course-generation convention). Optional `cover` attribute: markdown intro text shown on the assessment start screen, above the Start button.

```html
<form-assessment name='ff_HgRnAl7G3ThGayxvXm9IjrXmU4xq' title='Lesson 1: Assessment'
  required='true'
  cover='This quiz checks your understanding of the lesson. Answer every question correctly to pass.'
  questions='[
  {"id":"q1","label":"Which of these is a phishing indicator?","answers":[
    {"id":"a1","label":"Urgent tone and generic greeting","isCorrect":true},
    {"id":"a2","label":"Email from a known colleague","isCorrect":false},
    {"id":"a3","label":"Meeting invite for next Tuesday","isCorrect":false}
  ]},
  {"id":"q2","label":"What should you do if you receive a suspicious email?","answers":[
    {"id":"a1","label":"Reply to confirm","isCorrect":false},
    {"id":"a2","label":"Report it to the security team","isCorrect":true},
    {"id":"a3","label":"Forward it to colleagues","isCorrect":false}
  ]},
  {"id":"q3","label":"Which data is considered personal data?","answers":[
    {"id":"a1","label":"Public company financials","isCorrect":false},
    {"id":"a2","label":"Names combined with email addresses","isCorrect":true},
    {"id":"a3","label":"Aggregated anonymised metrics","isCorrect":false}
  ]}]'></form-assessment>
```

Critical rules:
- All attributes use **single** quotes (`name='...'`, not `name="..."`) because the JSON inside contains unescaped double quotes.
- **No apostrophes** anywhere inside `label` strings. They break the single-quoted attribute. Rephrase: `"the organisation"` not `"the organisation's"`, `"Upscaler platform"` not `"Upscaler's platform"`.
- Question/answer `id`s are simple sequential (`q1`, `q2`, `a1`, `a2`, `a3`) — do **not** call `generate_field_id` for these.
- At least one `isCorrect: true` per question; default to exactly one (platform convention). The runtime natively supports multiple correct answers — answers render as checkboxes and a question passes only when the learner selects exactly the set of `isCorrect: true` answers — so mark several answers correct only when the user explicitly asks for a select-all-that-apply question.
- `required='true'` always.
- `title='Lesson N: Assessment'`.
- `cover` is optional; the platform validates it as a plain string and renders it as markdown. Same single-quote and no-apostrophe rules apply.

### 17. `form-diagram` — never emit

Interactive drawing canvas; no generation path. (It *is* in the deserialiser whitelist, so an authored tag survives import, but there is no way to author a useful drawing value.)

### Recognised by the platform, but not authorable

- **`form-framework-requirement-picker`** ("Linked Requirements") is a real platform form field — its value is an array of `{frameworkId, requirementId}` objects, editing is admin-only, and it has no configurable options beyond the standard set — but it is **not** in the markdown authoring whitelist, so an authored `<form-framework-requirement-picker>` tag is silently dropped on create. The tag *can* appear in **exported** asset definitions (the serialiser emits it): recognise it when reading exported markdown, never author it, and expect it to vanish if such markdown is re-imported.
- **There is no `form-calculated` element.** Calculated values are an *option* on real fields: `calculated` + `formula` on `form-number`; `calculated` + `calculatorMode` (`"matrix"` or `"conditional"`) on `form-select` / `form-radio` / `form-checkbox`; matrix config on `form-text`. Do not emit a `<form-calculated>` tag — the deserialiser rejects unknown `form-*` tags and drops the block.

## Attachment elements (`<format-*>`)

Two tags only: `format-image` and `format-file`. Valid in every asset category. The platform strips the `format-` prefix and hoists HTML attributes onto the runtime Slate node, so `<format-image>` becomes `{ type: "image", ... }` and `<format-file>` becomes `{ type: "file", ... }`. No extra renderer needed.

### `format-image`

Attributes: `fileUid`, `fileName`, `alt`, `title`, `href`. Prefer the `fileUid` form: an `href`-only image renders solely in the editor's design mode (the read-only renderer reads only `fileUid`/`fileName`) and the markdown serialiser does not round-trip `href`. A `url` attribute is hoisted onto the node but never read by any code path.

```html
<format-image fileUid="<uid>" fileName="diagram.svg"></format-image>
```

Deserialises to:

```json
{ "type": "image", "fileUid": "<uid>", "fileName": "diagram.svg", "children": [{ "text": "" }] }
```

### `format-file`

Attributes: `fileList` (JSON array of file objects).

```html
<format-file fileList='[{"uid":"<uid>","name":"checklist.md","type":"text/markdown","size":1234,"status":"done"}]'></format-file>
```

Deserialises to:

```json
{ "type": "file", "fileList": [{ "uid": "<uid>", "name": "checklist.md", "type": "text/markdown", "size": 1234, "status": "done" }], "children": [{ "text": "" }] }
```

### Caveats

- **uids are platform-assigned.** Hand-crafted uids render as broken attachments. For **files**, `upscaler asset upload-file --field <name>` populates an existing `type: "file"` block and assigns the uid. For **images**, the CLI's `upload-file` ignores image blocks, so the only scripted path is presign + S3 POST through the SDK — see `03-document-authoring.md` → Workflow C for the Python snippet.
- **`status` and extra entry fields are transient.** The backend persists only `uid`, `name`, `type`, `size`, `addedAt` from each `fileList` entry and recomputes `status` from S3 on every read (`done` when the object exists), so `status:"done"` and `addedAt` in authored entries are optional. Blocks created via `<format-file>` carry no `options.name`, so `upscaler asset upload-file --field <name>` cannot target them later; only editor-inserted file blocks (which get `options: { name, title }`) are addressable by `--field`.
- **One-way syntax.** The Slate → markdown serializer always emits the URL form (`![filename](./_attachments/<uid>.<ext>)` for images, `[📎 filename](./_attachments/<uid>.<ext>)` for files). `<format-*>` is an authoring shortcut; re-exporting an asset never round-trips back to it.
- **Documents:** the standard placeholder + post-create upload workflow lets the editor place the block. `<format-*>` is only needed when scripting batch authoring with uids in hand. See `03-document-authoring.md` → Workflow C.

## Rating colour scale

For severity / likelihood / impact / priority ratings, use this fixed colour sequence:

| Level | Colour |
| --- | --- |
| 1 / Rare / Low | `green` |
| 2 / Unlikely | `cyan` |
| 3 / Possible / Medium | `gold` |
| 4 / Likely / High | `orange` |
| 5 / Almost certain / Critical | `volcano` (or `magenta` for the very top) |

Yes/No fields (where Yes is bad): `Yes`=`volcano`, `No`=`green`.

Full palette: `green, cyan, blue, gold, orange, volcano, magenta, purple, geekblue, lime`. Only use these.
